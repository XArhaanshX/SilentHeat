Why SilentHeat matters to Computer Science

B.Tech Computer Science and Engineering (SCOPE)

SilentHeat looks like a climate project, but most of the work is computer science: collecting data from an API, building a reproducible pipeline, implementing algorithms, training and validating machine-learning models, and shipping an interactive application. Probability and statistics are the theory underneath all of it.

Where our stream shows up in the project

CSE areaWhat we did in SilentHeat
Data engineering & APIsPulled 45 years of weather for 10 cities from the Open-Meteo REST API, parsed JSON, added retries and a local cache, then cleaned and joined 164,360 records into one feature table.
Algorithms & numerical computingWrote maximum-likelihood estimation for the GEV distribution from scratch and solved it with Nelder–Mead followed by BFGS optimisation. Also implemented the pairwise Mann–Kendall test, Monte Carlo simulation and bootstrap resampling, and checked our GEV code against a published package.
Machine learningFeature engineering (lags, rolling windows, physiology-based features), logistic regression, decision trees and random forests. A strict temporal train/validation/test split, threshold tuning on validation data only, leave-one-city-out generalisation, and evaluation with AUC, PR-AUC, Brier score and calibration.
Software engineeringA modular pipeline of 12 scripts with a single entry point (Rscript run_all.R), fixed random seeds for reproducible results, a dependency installer, and Git/GitHub version control with small, feature-by-feature commits. Running the full pipeline exposed a function-masking bug and a non-deterministic model, and we fixed both.
Web development & UIAn interactive R Shiny dashboard built on reactive programming. A user picks a city and a day and sees the official verdict and our model's verdict side by side.
Data visualisationSixteen figures in ggplot2, each produced in a dark theme for slides and a light theme for the report, with a colour-blind-safe palette.
AutomationThe written report and the slide deck are generated from the pipeline's output tables, so every number stays in sync with the code.

Why probability and statistics are core CS skills

  • Machine learning is applied probability. Logistic regression is a likelihood model, and random forests rely on bootstrap sampling. Calibration and Brier scores ask whether a model's probabilities can be trusted.
  • Hypothesis testing is A/B testing. The chi-square, McNemar and permutation tests we used are the same tools tech companies use to decide whether a feature change really helped.
  • Markov chains are everywhere in CS. They underlie PageRank, language models, queueing systems and reinforcement learning. We used one to model day-to-day persistence of danger.
  • Extreme-value theory is reliability engineering. The same GEV maths that gives Chennai's 50-year humid extreme is used to estimate p99 latency, server load peaks and failure rates.
  • Monte Carlo and the bootstrap are general computational techniques, also found in randomised algorithms, graphics and simulation.

Computing for social good

Heat is one of the deadliest climate hazards in India, and the people most exposed (outdoor workers, the elderly, people without cooling) depend on public warnings. Our hybrid alert keeps the government's rule and adds an ML layer, recovering 45% of the dangerous days the rule misses. Because the model also works in cities it was never trained on, it could scale to districts that lack long weather records. This is the kind of system CSE graduates build in public-health tech, climate-tech and government data teams.
